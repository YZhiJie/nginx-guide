第 6 章：静态资源优化与缓存策略 ​

本章目标：让静态资源飞起来——压缩、浏览器缓存、Nginx 代理缓存、零拷贝。 完成后可用 curl -H "Accept-Encoding: gzip" 验证压缩，用两次请求对比验证缓存命中。

6.1 静态资源优化总览 ​

四层优化手段，可叠加使用：

  1. 传输层：gzip/brotli 压缩，减少 70%+ 体积
  2. 浏览器层：Cache-Control + ETag，304 协商缓存
  3. Nginx 层：proxy_cache，反向代理结果本地缓存
  4. 内核层：sendfile / aio / directio，减少 CPU 拷贝

6.2 gzip 压缩 ​

6.2.1 基础配置 ​

nginx
# http 上下文（可放在 nginx.conf 或 snippets/gzip.conf）
gzip on;                          # 开启 gzip
gzip_vary on;                     # 添加 Vary: Accept-Encoding 响应头，让 CDN/代理缓存区分压缩版本
gzip_proxied any;                 # 即使请求经过代理也压缩（默认 only 直连）
gzip_comp_level 6;                # 压缩级别 1-9，6 是 CPU/压缩比的平衡点
gzip_min_length 1024;             # 小于 1KB 的响应不压缩（压缩开销大于收益）
gzip_buffers 16 8k;               # 压缩缓冲区

# 只对可压缩的文本类型启用，不要压缩已压缩格式（jpg/png/zip 越压越大）
gzip_types
    text/plain
    text/css
    text/xml
    text/javascript
    application/json
    application/javascript
    application/xml
    application/rss+xml
    application/atom+xml
    image/svg+xml;

6.2.2 gzip_static：预压缩静态文件 ​

构建时（如 webpack/vite）生成 .gz 文件，Nginx 直接发送，零 CPU 开销：

nginx
# 需要编译时加 --with-http_gzip_static_module（官方源默认已带）
location /assets/ {
    root /var/www/app;
    gzip_static on;      # 请求 app.js 时，若存在 app.js.gz 则直接发送
    expires 30d;
    add_header Cache-Control "public, immutable";
}

6.3 浏览器缓存策略 ​

6.3.1 强缓存（expires / Cache-Control） ​

nginx
# 策略一：带内容哈希的静态资源（immutable，永久缓存）
location /assets/ {
    root /var/www/app;
    expires 1y;
    add_header Cache-Control "public, immutable";
    # immutable 告诉浏览器：文件名变了内容才会变，不用发 304 验证
}

# 策略二：HTML 入口文件（不缓存或协商缓存，保证发版后立即生效）
location / {
    root /var/www/app;
    add_header Cache-Control "no-cache";   # 每次验证 ETag，304 快速响应
    # no-cache ≠ 不缓存，是「每次使用前必须验证」
}

# 策略三：图片等中等时效资源
location ~* \.(jpg|jpeg|png|gif|webp|svg|ico)$ {
    root /var/www/app;
    expires 30d;
    add_header Cache-Control "public";
}

6.4 Nginx 代理缓存（proxy_cache） ​

把后端响应缓存在 Nginx 本地，后端重启/慢速时直接返回缓存。

6.4.1 基础配置 ​

nginx
# http 上下文：定义缓存存储区
proxy_cache_path /var/cache/nginx/api
    levels=1:2                     # 两级目录，防止单目录文件过多
    keys_zone=api_cache:10m        # 共享内存区名:大小（存缓存 key 元数据，1MB ≈ 8000 key）
    max_size=1g                    # 磁盘缓存上限，超过按 LRU 淘汰
    inactive=60m                   # 60 分钟未被访问则删除（即使未过期）
    use_temp_path=off;             # 直接写入缓存目录，避免临时文件拷贝

server {
    listen 80;
    server_name api.test;

    location /api/ {
        proxy_pass http://backend/;

        proxy_cache api_cache;                      # 引用上面的 keys_zone
        proxy_cache_key "$scheme$request_method$host$request_uri";  # 缓存键
        proxy_cache_valid 200 302 10m;              # 200/302 响应缓存 10 分钟
        proxy_cache_valid 404 1m;                   # 404 缓存 1 分钟（防穿透）

        # 缓存状态头，便于调试
        add_header X-Cache-Status $upstream_cache_status;
    }
}

6.4.2 缓存状态与绕过 ​

$upstream_cache_status 的可能值：

值含义
MISS缓存未命中，回源获取并写入缓存
HIT缓存命中，直接返回
EXPIRED缓存过期，回源更新
BYPASS主动绕过缓存（见下）
STALE返回过期缓存（配合 proxy_cache_use_stale）
UPDATING缓存正在更新，返回旧版本
REVALIDATED缓存验证后仍有效
nginx
# 高级：绕过缓存 + 缓存锁 + 故障降级
location /api/ {
    proxy_pass http://backend/;
    proxy_cache api_cache;

    # 1) 带 nocache 参数时绕过缓存（管理员调试）
    proxy_cache_bypass $arg_nocache;

    # 2) 缓存锁：同一 key 同时只有一个请求回源，其余等待（防缓存击穿/惊群）
    proxy_cache_lock on;
    proxy_cache_lock_timeout 5s;

    # 3) 后端故障时返回过期缓存（防雪崩）
    proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;

    # 4) 最小使用次数：至少被请求 2 次才缓存（防止一次性请求污染缓存）
    proxy_cache_min_uses 2;

    add_header X-Cache-Status $upstream_cache_status;
}

6.5 内核级优化：零拷贝 ​

6.5.1 sendfile（必开） ​

nginx
http {
    sendfile on;         # 文件内容不经过用户态，内核直接发给网卡
    tcp_nopush on;       # 配合 sendfile，攒满一个包再发
    tcp_nodelay on;      # keepalive 状态下小包立即发
}

6.5.2 aio 与 directio（大文件场景） ​

nginx
http {
    sendfile on;
    aio threads;                    # 异步 IO 线程池（需 --with-threads 编译）
    aio_write on;
    directio 4m;                    # 大于 4MB 的文件用 directio 绕过页缓存
    directio_alignment 512;
    output_buffers 2 512k;          # 输出缓冲区
}

选型建议

场景配置
小文件（< 1MB，网页资源）sendfile on; 即可
大文件下载/视频（> 10MB）sendfile on; aio threads; directio 4m;
极高并发小文件考虑 SSD + 文件系统调优，Nginx 层保持默认

6.6 限流与带宽控制（静态资源保护） ​

nginx
# 限速：每个连接最大 1MB/s，前 10MB 不限速
location /downloads/ {
    root /var/www/files;
    limit_rate_after 10m;      # 前 10MB 全速
    limit_rate 1m;             # 之后限速 1MB/s
}

# 并发连接数限制
http {
    limit_conn_zone $binary_remote_addr zone=perip:10m;
}
server {
    location /downloads/ {
        limit_conn perip 5;    # 单 IP 最多 5 个并发下载连接
    }
}

本章小结 ​

  • 四层优化：gzip 压缩（传输）→ 浏览器缓存（客户端）→ proxy_cache（Nginx 层）→ sendfile（内核层）
  • 带 hash 的静态资源：expires 1y + immutable；HTML：no-cache 协商缓存
  • proxy_cache 三件套防雪崩：proxy_cache_lock（防击穿）+ proxy_cache_use_stale（防雪崩）+ proxy_cache_valid 404（防穿透）
  • 大文件场景用 aio threads + directio；小文件 sendfile 足够

常见坑 ​

  1. gzip 压缩已压缩格式：jpg/png/zip 开 gzip 反而变大且耗 CPU，gzip_types 只放文本类型
  2. proxy_cache 缓存了个性化响应：带 Cookie 的响应默认不缓存（Nginx 检测到 Set-Cookie 会跳过），若需缓存需显式 proxy_ignore_headers Set-Cookie;（危险，确认无用户态数据）
  3. expires 与 Cache-Control 冲突：两者同时存在时 Cache-Control 优先；expires 指令会自动生成对应的 Cache-Control
  4. proxy_cache_path 目录权限：cache manager 进程以 nginx 用户运行，目录必须可写：chown -R nginx:nginx /var/cache/nginx
  5. 缓存键遗漏 query 参数：默认 $request_uri 含 query；若 query 中有随机参数（如 ?_t=123）会导致缓存永不命中，需自定义 proxy_cache_key 剔除
