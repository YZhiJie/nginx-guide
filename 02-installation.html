第 2 章：多平台安装步骤 ​

本章目标：在 Linux、macOS、Windows、Docker 上装好 Nginx，并理解包安装与源码编译的取舍。 完成后可执行 nginx -v / nginx -V 并通过 curl 看到默认欢迎页。

2.1 安装方式总览 ​

方式优点缺点推荐场景
系统包管理器一键、集成 systemd版本可能偏旧、模块受限快速上手/生产通用
官方源（nginx.org）版本新、跟随主线需配置 repo生产推荐
源码编译自定义模块/极致裁剪维护成本高需要三方模块/特殊参数
Docker环境隔离、易编排需懂容器网络云原生/本地复现

2.2 Linux 安装 ​

2.2.1 Debian / Ubuntu（apt，推荐官方源） ​

bash
# 1) 安装依赖
sudo apt update && sudo apt install -y curl gnupg2 ca-certificates lsb-release ubuntu-keyring

# 2) 导入官方签名 key（防止中间人篡改包）
curl -fsSL https://nginx.org/keys/nginx_signing.key | \
  sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg

# 3) 添加稳定版源（主线把 stable 改成 mainline）
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] \
http://nginx.org/packages/ubuntu $(lsb_release -cs) nginx" | \
  sudo tee /etc/apt/sources.list.d/nginx.list

# 4) 提高官方源优先级，避免被发行版旧版覆盖
echo -e "Package: *\nPin: origin nginx.org\nPin: release o=nginx\nPin-Priority: 900\n" | \
  sudo tee /etc/apt/preferences.d/99nginx

# 5) 安装并启动
sudo apt update && sudo apt install -y nginx
sudo systemctl enable --now nginx

2.2.2 RHEL / CentOS / Rocky / Alma（yum/dnf） ​

bash
# 1) 创建官方源
sudo tee /etc/yum.repos.d/nginx.repo <<'EOF'
[nginx-stable]
name=nginx stable repo
baseurl=http://nginx.org/packages/centos/$releasever/$basearch/
gpgcheck=1
enabled=1
gpgkey=https://nginx.org/keys/nginx_signing.key
module_hotfixes=true
EOF

# 2) 安装并放行防火墙
sudo dnf install -y nginx
sudo systemctl enable --now nginx
sudo firewall-cmd --permanent --add-service=http --add-service=https
sudo firewall-cmd --reload

2.2.3 源码编译（需要三方模块时） ​

bash
# 1) 安装构建依赖（以 Ubuntu 为例）
sudo apt install -y build-essential libpcre3-dev zlib1g-dev libssl-dev

# 2) 下载并解压
wget https://nginx.org/download/nginx-1.26.2.tar.gz
tar xzf nginx-1.26.2.tar.gz && cd nginx-1.26.2

# 3) 配置（常用编译选项说明见下表）
./configure \
  --prefix=/etc/nginx \
  --sbin-path=/usr/sbin/nginx \
  --conf-path=/etc/nginx/nginx.conf \
  --error-log-path=/var/log/nginx/error.log \
  --http-log-path=/var/log/nginx/access.log \
  --with-http_ssl_module \
  --with-http_v2_module \
  --with-http_realip_module \
  --with-http_gzip_static_module \
  --with-threads \
  --with-file-aio \
  --with-stream \
  --with-compat            # 支持动态模块热加载

# 4) 编译安装
make -j$(nproc) && sudo make install

常用编译选项速查

选项作用何时需要
--with-http_ssl_moduleHTTPS/TLS生产必须
--with-http_v2_moduleHTTP/2生产必须
--with-http_realip_module获取真实客户端 IP前面有 CDN/LB
--with-threads + --with-file-aioaio 线程池大文件/视频
--with-stream四层 TCP/UDP 代理代理 MySQL/Redis
--add-module=/path/xxx静态编译三方模块如 headers-more
--add-dynamic-module=/path/xxx编译为 .so 动态模块配合 --with-compat 热加载

2.4 Windows 安装 ​

powershell

2.5 Docker 安装（本地复现/CI） ​

bash
# 启动一个挂载本地配置的容器
docker run -d --name web \
  -p 8080:80 \
  -v $PWD/nginx-comprehensive-guide/examples/basic/nginx.conf:/etc/nginx/nginx.conf:ro \
  -v $PWD/examples/basic/html:/usr/share/nginx/html:ro \
  nginx:1.26-alpine

# 重载配置
docker exec web nginx -s reload
# 查看日志
docker logs -f web

2.6 验证安装（统一方法） ​

bash
# 1) 版本与编译参数
nginx -v
nginx -V 2>&1 | tr ' ' '\n' | grep with   # 查看已启用模块

# 2) 配置语法校验（每次改配置必做）
sudo nginx -t

# 3) 查看进程与端口
ps aux | grep nginx
sudo lsof -i :80 -sTCP:LISTEN

# 4) HTTP 验证
curl -I http://127.0.0.1:80
# 期望输出 HTTP/1.1 200 OK 与 Server: nginx/x.x.x

2.7 关键目录与命令速查 ​

用途Debian/UbuntuRHEL/CentOSmacOS(brew)源码
主配置/etc/nginx/nginx.conf同左/opt/homebrew/etc/nginx/nginx.conf--conf-path 指定
站点配置/etc/nginx/conf.d/.conf 或 sites-/etc/nginx/conf.d/servers/conf.d/
日志/var/log/nginx/同左/opt/homebrew/var/log/nginx/--http-log-path
PID/run/nginx.pid同左/opt/homebrew/var/run/nginx.pid--pid-path
启动systemctl start nginx同左brew services start nginx手动/nginx

进程控制信号

命令信号作用
nginx -s reloadHUP平滑重载配置（旧 worker 处理完现有请求后退出）
nginx -s reopenUSR1重开日志文件（配合日志切割）
nginx -s stopTERM立即停止
nginx -s quitQUIT优雅停止（等请求处理完）

本章小结 ​

  • 生产用「官方源 + systemd」，快速试验用 Docker，三方模块用源码编译
  • 改配置三步走：编辑 → nginx -t → nginx -s reload
  • 记住你的平台的关键路径与日志位置，排障时第一站就是它们

常见坑 ​

  1. 端口被占：Address already in use → sudo lsof -i :80 找占用进程（常见是 Apache/已启动的 nginx）
  2. 权限不足：80/443 是特权端口，非 root 启动会报 Permission denied，用 systemd 或 sudo
  3. 官方源不生效：Debian/Ubuntu 需确认 99nginx pin 优先级，否则装的仍是发行版旧版
  4. 防火墙/安全组：云服务器记得放行 80/443（如 firewall-cmd、云控制台安全组）
