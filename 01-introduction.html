第 1 章：Nginx 简介与核心优势 ​

本章目标：理解 Nginx 是什么、为什么快、什么时候该用它。 阅读时间约 15 分钟。

1.1 Nginx 是什么 ​

Nginx（发音 "engine-x"）是一款事件驱动的开源软件，由 Igor Sysoev 于 2004 年发布，最初为解决 C10K 问题（单机 1 万并发连接）而设计。今天它是全球占有率第一的 Web 服务器，同时具备四大角色：

  1. Web 服务器：直接高效分发静态资源（HTML/CSS/JS/图片/视频）
  2. 反向代理服务器：将请求转发给后端应用（Node/Go/Java/PHP-FPM）
  3. 负载均衡器：在多个上游实例间分发流量
  4. API 网关 / 边缘层：SSL 终结、限流、鉴权、灰度发布的统一入口

1.2 架构模型：为什么 Nginx 快 ​

1.2.1 Master-Worker 进程模型 ​

  • Master：以 root 启动，只负责读配置、绑定端口、管理 worker 生命周期，不处理请求
  • Worker：单线程 + 非阻塞事件循环（Linux 用 epoll，macOS/BSD 用 kqueue），每个 worker 可维持数万并发连接
  • 无锁化：worker 之间不共享状态，避免锁竞争；每个连接按 round-robin 被 accept（受 accept_mutex / reuseport 调度）

1.2.2 事件驱动 vs 进程/线程模型（对比 Apache） ​

维度Nginx（事件驱动）Apache prefork（多进程）
并发单位事件（连接复用 worker）一个连接占一个进程/线程
万级并发内存几十 MB（连接结构体 ~256B/个）数 GB（每进程 5-15MB）
上下文切换极少频繁（CPU 浪费在调度）
动态模块热加载支持（1.9.11+）支持
平滑升级/重载reload 零中断重启有抖动

1.2.3 请求处理流水线（简化） ​

关键结论：Nginx 的高并发能力来自「单线程事件循环 × 多 worker × 操作系统零拷贝」，而不是堆线程数。

1.5 Nginx vs 常见替代方案 ​

维度NginxApache httpdCaddyEnvoy
定位通用 Web/代理通用 Web自动 HTTPS 现代服务器云原生 L4/L7 代理
配置风格声明式 conf.htaccess/confCaddyfileYAML/动态 xDS
性能极高中高极高
学习曲线中中低高
适合生产主力、生态成熟存量系统、PHP 共享托管小团队快速上线服务网格/大规模动态路由

选型建议：需要稳定、生态、性能与资料覆盖，Nginx 仍是默认答案；纯新项目且追求极简 HTTPS，可评估 Caddy；服务网格数据面选 Envoy。

1.6 版本选择 ​

  • Mainline（主线）：1.27.x，功能新，生产可用（官方承诺同样稳定）
  • Stable（稳定）：1.26.x，仅合 bugfix，保守型生产首选
  • 开源版 vs NGINX Plus：Plus 为商业版（动态 upstream API、原生健康检查、监控面板）。本教程全部基于开源版可实现的能力编写，并标注需要 Plus 的替代方案。

本章小结 ​

  • Nginx = 事件驱动、多 worker、单线程非阻塞的 Web/代理服务器
  • 快的原因：连接复用 worker + 零拷贝 + 无锁 + 热部署
  • 记住 4 大角色：静态服务、反向代理、负载均衡、边缘网关

效果验证：阅读后能用自己的话解释「为什么 Nginx 单机可支撑 10 万连接」；可执行 nginx -v 确认后续章节环境。

常见坑（前置提示） ​

  • 不要把 Nginx 当「应用容器」用：业务逻辑放后端，Nginx 只做转发/卸载/缓存
  • reload 不丢请求，但 restart 会有毫秒级闪断，生产统一用 reload
