第 8 章：日志管理与分析 ​

本章目标：掌握 Nginx 日志的格式定制、切割归档、实时分析与告警。 完成后能用 GoAccess 实时看板分析流量，并能配置 logrotate 自动切割日志。

8.1 日志体系总览 ​

日志类型记录内容级别可配位置指令

8.2 access_log 详解 ​

8.2.1 默认格式（combined） ​

nginx
# Nginx 内置 combined 格式等价于：
log_format combined '$remote_addr - $remote_user [$time_local] '
                    '"$request" $status $body_bytes_sent '
                    '"$http_referer" "$http_user_agent"';

8.2.2 自定义格式（生产推荐：含性能指标） ​

nginx
# examples/logging/log-formats.conf
# 性能分析格式：重点加上游耗时与请求耗时
log_format perf '$remote_addr - [$time_local] "$request" '
                '$status $body_bytes_sent '
                'rt=$request_time urt=$upstream_response_time '
                'ua="$http_user_agent" '
                'xff="$http_x_forwarded_for" '
                'cache="$upstream_cache_status" '
                'upstream="$upstream_addr"';

# JSON 格式：对接 ELK/Loki 等日志系统（推荐生产使用）
log_format json_combined escape=json
    '{'
        '"time":"$time_iso8601",'
        '"remote_addr":"$remote_addr",'
        '"method":"$request_method",'
        '"uri":"$uri",'
        '"query":"$args",'
        '"status":$status,'
        '"bytes":$body_bytes_sent,'
        '"request_time":$request_time,'
        '"upstream_time":"$upstream_response_time",'
        '"upstream_addr":"$upstream_addr",'
        '"cache_status":"$upstream_cache_status",'
        '"referer":"$http_referer",'
        '"user_agent":"$http_user_agent",'
        '"xff":"$http_x_forwarded_for",'
        '"request_id":"$request_id"'
    '}';

server {
    listen 80;
    # 使用 JSON 格式，便于机器解析
    access_log /var/log/nginx/access.log json_combined;
}

关键变量说明

变量含义排障价值
$request_time完整请求耗时（从读第一个字节到写完响应）总延迟
$upstream_response_time后端响应耗时区分 Nginx 慢还是后端慢
$upstream_connect_time与后端建连耗时后端网络/TCP 队列问题
$upstream_header_time收到后端响应头耗时后端处理慢
$request_idNginx 生成的唯一请求 ID（1.11.0+）分布式链路追踪
$upstream_cache_status缓存命中状态缓存命中率分析

8.2.3 条件日志（减少磁盘 IO） ​

nginx
# 跳过健康检查与静态资源的日志（高流量站点节省 50%+ 日志量）
map $uri $loggable {
    /healthz        0;
    /favicon.ico    0;
    ~*\.(js|css|png|jpg|ico)$  0;   # 静态资源不记录（可选）
    default         1;
}

# 只记录非 2xx/3xx（异常流量审计）
map $status $log_errors {
    ~^[23]  0;
    default 1;
}

server {
    # 条件记录：$loggable=1 才写日志
    access_log /var/log/nginx/access.log json_combined if=$loggable;

    # 错误单独一份日志
    access_log /var/log/nginx/errors.log json_combined if=$log_errors;
}

8.2.4 日志缓冲（性能优化） ​

nginx
# buffer：内存缓冲写日志，减少磁盘 IO
# flush：缓冲满或超时后刷盘
access_log /var/log/nginx/access.log json_combined buffer=64k flush=5s;

# gzip：写入时压缩（节省磁盘，略增 CPU）
access_log /var/log/nginx/access.log.gz json_combined gzip buffer=64k flush=5s;

8.3 error_log 详解 ​

nginx
# 全局（main 上下文）
error_log /var/log/nginx/error.log warn;

# 调试模式（需 --with-debug 编译；线上慎开，量极大）
error_log /var/log/nginx/debug.log debug;

# 按模块过滤调试日志（如只调试 rewrite）
error_log /var/log/nginx/rewrite-debug.log debug rewrite;

级别从低到高：debug → info → notice → warn → error → crit → alert → emerg

生产建议：warn。error 级别会漏掉 open() failed (13: Permission denied) 这类 403 根因日志（属于 error 级别，warn 会包含）。

error_log 常见报错对照表

报错含义处理
open() "/path" failed (13: Permission denied)文件权限不足chown/chmod
connect() failed (111: Connection refused)后端未启动/端口不通检查后端进程
upstream timed out (110: Connection timed out)后端响应超时调 proxy_read_timeout 或优化后端
worker_connections are not enough连接数打满调 worker_connections，见第 9 章

8.4 日志切割：logrotate ​

Nginx 本身不做日志切割（会持续写同一个文件），用系统 logrotate：

bash
# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily                   # 每天切割
    rotate 14               # 保留 14 天
    missingok               # 日志不存在不报错
    compress                # gzip 压缩旧日志
    delaycompress           # 最新一份不压缩（方便排查）
    notifempty              # 空日志不切割
    sharedscripts           # 所有日志只执行一次 postrotate
    postrotate
        # 通知 Nginx 重开日志文件（USR1 信号）
        [ -f /run/nginx.pid ] && kill -USR1 $(cat /run/nginx.pid)
    endscript
}

8.5 实时分析工具 ​

8.5.1 GoAccess（终端实时看板，推荐） ​

bash
# 安装
brew install goaccess          # macOS
sudo apt install goaccess      # Ubuntu

# 实时终端分析（指定 combined 格式）
goaccess /var/log/nginx/access.log \
  --log-format=COMBINED \
  --real-time-html \
  -o /var/www/report.html

# 配合 JSON 日志格式
goaccess /var/log/nginx/access.log \
  --log-format='{"time":"%dT%t","remote_addr":"%h",...}' \
  --date-format='%Y-%m-%d' --time-format='%T'

# 常用快捷统计（不进交互界面）
goaccess /var/log/nginx/access.log --log-format=COMBINED \
  --sort-panel=REQUESTS,BY_DATA,DESC   # 按访问量排序

8.5.3 命令行快速分析（awk 一把梭） ​

bash
# Top 10 IP
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# Top 10 URL
awk '{print $7}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 统计状态码分布
awk '{print $9}' /var/log/nginx/access.log | sort | uniq -c | sort -rn

# 找出平均响应最慢的 URL（配合 perf 格式）
awk -F'rt=' '{split($2,a," "); print $7, a[1]}' /var/log/nginx/access.log | \
  awk '{sum[$1]+=$2; cnt[$1]++} END {for(u in sum) printf "%.3fs %s\n", sum[u]/cnt[u], u}' | \
  sort -rn | head

# 每分钟 QPS 曲线
awk '{split($4,a,":"); print a[1]":"a[2]":"substr(a[3],1,2)}' /var/log/nginx/access.log | \
  uniq -c | awk '{print $2, $1}'

8.6 日志驱动的告警规则（示例） ​

bash
# 简单 Shell 告警：5 分钟内 5xx 超过阈值发通知
#!/bin/bash
# check-5xx.sh（cron 每分钟执行）
LOG=/var/log/nginx/access.log
THRESHOLD=50
COUNT=$(awk -v d="$(date -d '5 min ago' '+%d/%b/%Y:%H:%M')" \
  '$4 > "["d && $9 >= 500 {c++} END {print c+0}' $LOG)

if [ "$COUNT" -gt "$THRESHOLD" ]; then
    curl -X POST "https://qyapi.weixin.qq.com/.../webhook/send" \
      -d "{\"msgtype\":\"text\",\"text\":{\"content\":\"Nginx 5xx 告警: ${COUNT} 条/5min\"}}"
fi

本章小结 ​

  • 生产用 JSON 格式（escape=json），机器解析友好；排查期用 perf 格式（带 rt/urt）
  • 条件日志（map + if=）过滤健康检查与静态资源，节省一半磁盘
  • 切割用 logrotate + USR1 信号，不要用 copytruncate
  • 快速排查：awk 三板斧（Top IP / Top URL / 状态码分布）；持续监控：GoAccess 或 ELK/Loki
  • $request_time 与 $upstream_response_time 对比是区分「Nginx 慢」与「后端慢」的关键

常见坑 ​

  1. 日志不写入：磁盘满（df -h）或权限不对；Nginx worker 需对日志目录有写权限
  2. 切割后日志写进旧文件：logrotate 的 postrotate 没发 USR1，或 PID 文件路径不对
  3. JSON 日志中变量含引号/换行导致解析失败：必须用 escape=json，否则 " 会破坏 JSON 结构
  4. $upstream_response_time 出现多个值或 -：upstream 重试多次时逗号分隔；- 表示未回源（如命中缓存）
  5. time_local 时区不对：Nginx 用系统时区，容器内需挂 /etc/localtime 或设 TZ 环境变量
