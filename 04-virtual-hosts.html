第 4 章：虚拟主机配置 ​

本章目标：用一台 Nginx 服务器托管多个站点，掌握基于域名、端口、IP 的三种虚拟主机模式。 完成后可通过不同域名/端口访问到各自独立的站点目录。

4.1 什么是虚拟主机 ​

虚拟主机（Virtual Host）指一台物理/云服务器上运行多个网站，它们共用同一个 Nginx 进程，但通过请求特征（域名、端口、IP）被路由到不同的配置块。Nginx 天然擅长此场景，一个 server 块即一个虚拟主机。

4.2 基于域名的虚拟主机（最常用） ​

配置示例 ​

nginx
# /etc/nginx/conf.d/hosts.conf
# --------------------------------------------------
# 站点 A：个人博客
# --------------------------------------------------
server {
    listen 80;
    server_name blog.test www.blog.test;

    root /var/www/blog;
    index index.html index.htm;

    location / {
        try_files $uri $uri/ =404;
    }

    # 静态资源缓存（第6章详解）
    location ~* \.(jpg|jpeg|png|gif|ico|css|js)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}

# --------------------------------------------------
# 站点 B：电商商城
# --------------------------------------------------
server {
    listen 80;
    server_name shop.test www.shop.test;

    root /var/www/shop;
    index index.html;

    # API 请求代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
        include /etc/nginx/snippets/proxy-headers.conf;
    }

    # 前端 SPA 回退
    location / {
        try_files $uri $uri/ /index.html;
    }
}

# --------------------------------------------------
# 默认站点（兜底，避免未知域名暴露内部配置）
# --------------------------------------------------
server {
    listen 80 default_server;    # default_server 标记为默认主机
    server_name _;               # 匹配任意 Host（或没有 Host）

    return 444;                  # 444 是 Nginx 特殊码：直接断开连接，不返回任何响应
    # 生产建议改为 return 301 https://www.example.com$request_uri; 做安全兜底
}

server_name 匹配规则 ​

nginx
server {
    listen 80;
    # 多域名并列（空格分隔）
    server_name blog.test www.blog.test;
}

server {
    listen 80;
    # 通配符开头：匹配任意子域名
    server_name *.blog.test;
}

server {
    listen 80;
    # 通配符结尾：匹配 blog.test 及所有后缀
    server_name blog.*;
}

server {
    listen 80;
    # 正则匹配（~ 开头），注意点号要转义
    server_name ~^www\d+\.blog\.test$;
}

4.3 基于端口的虚拟主机 ​

nginx
# /etc/nginx/conf.d/ports.conf
server {
    listen 8080;
    server_name _;          # 不限制域名，任何 Host 都走这里

    root /var/www/dev;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

server {
    listen 8081;
    server_name _;

    root /var/www/staging;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}

4.5 HTTPS 多域名（SNI） ​

现代浏览器/客户端都支持 SNI（Server Name Indication），Nginx 只需监听同一个 443 端口即可通过域名分发不同的证书：

nginx
server {
    listen 443 ssl http2;
    server_name blog.test;

    ssl_certificate     /etc/nginx/ssl/blog.test/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/blog.test/privkey.pem;

    root /var/www/blog;
}

server {
    listen 443 ssl http2;
    server_name shop.test;

    ssl_certificate     /etc/nginx/ssl/shop.test/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/shop.test/privkey.pem;

    root /var/www/shop;
}

4.6 默认服务器与隐式行为 ​

当多个 server 监听同一个 IP:PORT 时，Nginx 按以下规则选择：

  1. listen ... default_server 显式标记的优先
  2. 否则取配置文件中第一个出现的该 IP:PORT 的 server
  3. 然后根据 server_name 做二次匹配（不匹配则落到默认 server）
nginx
# 陷阱：这个 server 隐式成为默认服务器（如果没其他人设 default_server）
server {
    listen 80;
    server_name old.test;
    # 若客户端 Host 头为空，或 Host 未匹配任何 server_name，
    # 会落到这个 server，可能暴露不该暴露的内容
}

# 正确做法：始终显式定义一个兜底的 default_server
server {
    listen 80 default_server;
    server_name _;
    return 444;     # 或直接 301 跳转到主站
}

conf.d/

├── 443-blog.test.conf      # HTTPS 配置

本章小结 ​

类型判断依据使用频率注意
基于域名Host 头★★★★★生产主流；务必设 default_server 兜底
基于端口listen 端口★★环境隔离、内部后台常用
基于 IPlisten IP★多公网 IP 场景
  • server_name 支持精确、通配符、正则三种匹配；优先级依次降低
  • 多个 server 监听同一端口时，没匹配的请求会落到默认 server（第一个或 default_server）
  • 生产建议始终配置一个返回 444 或 301 的兜底 server，防止信息泄露

常见坑 ​

  1. hosts 文件改完浏览器不生效：浏览器缓存/操作系统 DNS 缓存；Chrome 可开隐身模式，Linux 可 sudo systemd-resolve --flush-caches
  2. default_server 放错位置：不是写在第一个就有效，必须显式加 default_server 关键字
  3. server_name 带端口写错：server_name blog.test:8080 是错误的，端口写在 listen 里
  4. SNI 旧客户端不支持：极少数 IoT/老旧设备，如需兼容可改用多 IP 方案
