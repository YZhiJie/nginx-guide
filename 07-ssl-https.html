第 7 章：SSL/TLS 配置与 HTTPS 部署 ​

本章目标：从零部署生产级 HTTPS——证书申请、TLS 配置、HTTP/2、安全加固、自动续期。 完成后通过 SSL Labs 检测达到 A/A+ 评级。

7.1 HTTPS 工作原理（速览） ​

关键点：

  • 非对称加密（证书公钥/私钥）只用于握手阶段交换密钥
  • 对称加密（AES-GCM/ChaCha20）用于实际数据传输（快 1000 倍）
  • TLS 1.3 比 1.2 少一次往返（1-RTT vs 2-RTT），握手更快更安全

7.2 证书获取 ​

7.2.1 免费证书：Let's Encrypt（生产推荐） ​

bash
# 1) 安装 certbot（Ubuntu）
sudo apt install -y certbot python3-certbot-nginx

# 2) 一键申请并自动配置 Nginx（需要域名已解析到服务器，80 端口可达）
sudo certbot --nginx -d example.com -d www.example.com

# 3) 验证自动续期（Let's Encrypt 证书 90 天有效期）

7.3 生产级 HTTPS 配置模板 ​

nginx
# examples/ssl/https-production.conf
# --------------------------------------------------
# HTTP → HTTPS 强制跳转
# --------------------------------------------------
server {
    listen 80;
    server_name example.com www.example.com;

    # ACME 挑战路径（certbot 续期用，必须放行）
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    # 其余请求全部 301 跳转到 HTTPS
    location / {
        return 301 https://$host$request_uri;
    }
}

# --------------------------------------------------
# HTTPS 主站
# --------------------------------------------------
server {
    listen 443 ssl;
    http2 on;                    # ← 注意：1.25.1+ 用 http2 on; 替代 listen ... http2
    server_name example.com www.example.com;

    # ---- 证书配置 ----
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # ---- TLS 版本与加密套件（Mozilla Intermediate 基线）----
    ssl_protocols TLSv1.2 TLSv1.3;     # 禁用 TLS 1.0/1.1（已知漏洞）
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305';
    ssl_prefer_server_ciphers off;     # TLS 1.3 下客户端优先，更安全

    # ---- 会话复用（性能关键）----
    ssl_session_timeout 1d;                    # 会话票据有效期
    ssl_session_cache shared:SSL:50m;          # 所有 worker 共享会话缓存（1MB ≈ 4000 会话）
    ssl_session_tickets off;                   # 关闭 session ticket（完美前向保密 PFS 考虑）

    # ---- OCSP Stapling（客户端省去在线验证）----
    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/example.com/chain.pem;
    resolver 223.5.5.5 8.8.8.8 valid=300s;    # 国内用阿里 DNS，海外用 8.8.8.8
    resolver_timeout 5s;

    # ---- 安全响应头 ----
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

    root /var/www/example;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}

HTTP/2 优势：多路复用（单连接并行请求）、头部压缩（HPACK）、服务器推送（已弃用）。 前提：必须先启用 HTTPS（浏览器强制要求 H2 over TLS）。

7.4.2 HSTS（强制 HTTPS） ​

nginx
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
1
  • max-age=63072000：2 年内浏览器只走 HTTPS，即使输入 http://
  • includeSubDomains：所有子域名同样强制
  • preload：申请加入浏览器内置 HSTS 列表（需到 https://hstspreload.org 提交）
  • 警告：开启 preload 前确认所有子域名都有证书，否则子站会无法访问

7.5 HTTP/3 (QUIC) 前瞻 ​

nginx
# Nginx 1.25.0+ 实验性支持 HTTP/3
server {
    listen 443 ssl;
    listen 443 quic reuseport;    # QUIC 走 UDP
    http2 on;
    http3 on;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    # 告诉客户端支持 HTTP/3
    add_header Alt-Svc 'h3=":443"; ma=86400' always;
}

7.6 证书自动续期 ​

bash
# certbot 自动续期（系统级 timer）
sudo systemctl list-timers | grep certbot
# 或手动加 cron（每天检查两次，临期才续）
0 0,12 * * * root certbot renew --quiet --deploy-hook "nginx -s reload"

# 测试续期流程（不会真的续）
sudo certbot renew --dry-run

# 查看证书到期时间
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | \
  openssl x509 -noout -dates

7.7 效果验证（完整清单） ​

7.7.1 本地验证 ​

bash
# 1) 配置语法
sudo nginx -t

# 2) TLS 握手与证书信息
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | \
  openssl x509 -noout -subject -issuer -dates

# 3) 验证 TLS 1.3
curl -I --tlsv1.3 --tls-max 1.3 https://example.com
# 期望：HTTP/2 200

# 4) 验证 HTTP/2
curl -I --http2 https://example.com
# 期望：HTTP/2 200

# 5) 验证 HTTP 跳转 HTTPS
curl -I http://example.com
# 期望：301 Moved Permanently → Location: https://...

# 6) 验证 HSTS
curl -sI https://example.com | grep -i strict-transport
# 期望：strict-transport-security: max-age=63072000; ...

# 7) 验证拒绝旧版 TLS
curl -I --tlsv1.0 --tls-max 1.0 https://example.com
# 期望：握手失败（curl: (35) ...）

7.8 安全基线速查（生产 Checklist） ​

  • [ ] ssl_protocols 只保留 TLSv1.2 + TLSv1.3
  • [ ] 证书私钥权限 600，属 root
  • [ ] HSTS 开启（先 short max-age 测试，再加长 + preload）
  • [ ] HTTP 全量 301 跳转 HTTPS
  • [ ] OCSP Stapling 开启 + resolver 配置
  • [ ] 安全响应头齐全（X-Frame-Options / nosniff / Referrer-Policy）
  • [ ] 证书自动续期 + 到期监控告警
  • [ ] 私钥泄露应急预案（吊销 + 重签流程）

本章小结 ​

  • 生产用 Let's Encrypt + certbot 自动续期；本地用 mkcert
  • TLS 1.2 + 1.3 双开，http2 on 独立指令（1.25.1+）
  • 性能三件套：会话缓存（shared）、OCSP Stapling、TLS 1.3 的 1-RTT
  • HSTS 加 preload 前必须确认全子域名 HTTPS 就绪
  • SSL Labs 评分 A+ 是生产交付标准

常见坑 ​

  1. 证书链不完整：浏览器报 unable to get local issuer certificate → 必须合并中间证书为 fullchain.pem（域名证书在前）
  2. add_header 继承失效：子 location 定义了 add_header 会覆盖父级全部 → 安全头统一用 include snippet
  3. OCSP Stapling 失败：resolver 未配置或 DNS 不通；启动时证书域名还没解析也会导致 stapling 静默失败
  4. HTTP/2 后 NPN 警告：新版 Chrome 用 ALPN，Nginx 1.14+ 配合 OpenSSL 1.0.2+ 自动支持，旧版需升级
  5. 续期后忘记 reload：certbot renew 成功但 Nginx 仍用旧证书 → 必须配 --deploy-hook "nginx -s reload"
